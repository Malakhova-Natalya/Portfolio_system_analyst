# Понимание профессии системного аналитика

## Контекст
Чтобы закрепить полученные теоретические знания, необходимо выполнить практическое задание: выбрать один из кейсов на выбор и расписать по нему состав команды, модель управления и пр.

## Задача 
Необходимо собрать проектную команду и определить первые шаги для выполнения поставленной задачи по проекту

Выбранный кейс:

> Разработка функционала поиска для интернет-магазина.
> 
> В рамках проекта команда создает новый раздел с умным поиском товаров на сайте.
> Проект амбициозный и большой. Заказчик хочет, чтобы поиск можно было выполнять по всевозможным запросам и крите- риям, чтобы был голосовой поиск и еще поиск по загруженным картинкам и еще много-много всего.
> 
> Заказчик: «Мы должны предоставлять пользователям самый современный поиск!»

## Решение
## Выбор кейса и модели управления

> **1. Выберите кейс, который решаешь:**

Поиск для интернет-магазина

> **2. Выбери модель управления для реализации проекта:**

Agile

> **3. Опиши, почему ты выбрал именно такую модель управления для проекта?**

| _По описанию:_ |
| --- |
| — _проект большой («Проект амбициозный и большой»)_ |
| — _со всевозможными требованиями (чтобы было X, Y, Z и «ещё много-много всего»)_ |
| — _на старте неизвестны сроки, чёткие параметры, ограничения. При этом поиск здесь читается как продукт, который хочется совершенствовать («Мы должны предоставлять пользователям самый современный поиск!»)_ |
| _**По совокупности отношу это к продуктовой разработке (а не проектной).**_ |
| _В продуктовой разработке выбор ограничивается Agile или методом набегающей волны. В принципе, здесь можно рассмотреть оба подхода, но, поскольку нужно выбрать один, я выбираю Agile как наиболее адаптивный и гибкий._ |
| _По описанию вижу разные смысловые блоки (запросы, голосовой поиск, поиск по картинкам), но есть сомнения, что из этого можно составить устойчивый и последовательный roadmap («и ещё много-много всего», «самый современный поиск!»). Вдруг заказчик придёт с запросом: «а теперь внедряем ИИ. Срочно!». В такой ситуации Agile видится наиболее адаптивным и, следовательно, более подходящим подходом._ |

**4. Почему не подходят другие модели?**

| Ответ |
| --- |
| _**Каскадная модель:** относится к проектной разработке, а у нас продуктовая. Поэтому нам не подходит (у нас нет сроков, ограничений, последовательного плана)._ |
| _**Метод набегающей волны:** в принципе, она может подойти, но мой выбор — Agile. Метод набегающей волны, возможно, недостаточно гибок — в описании нет последовательности и всех пожеланий, чтобы на весь проект иметь примерный план (он может измениться, дополниться, пересмотреться в каких-то аспектах — и для такой ситуации выбираю Agile)._ |
